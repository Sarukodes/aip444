Prompt engineering is the process of writing clear instructions for an AI model so that its output is more accurate and useful.

Clear prompts help reduce hallucinations and improve consistency in responses. A poorly written prompt may confuse the model and produce unreliable answers.

Delimiters such as XML tags or Markdown code blocks help separate user data from instructions. This prevents the model from confusing notes with commands.

Prompt injection happens when a user attempts to insert malicious instructions into the prompt. Delimiters help reduce this risk.

Few-shot prompting means giving the model examples before asking it to complete a task. These examples help the model understand the format and style expected.

Zero-shot prompting means asking the model to complete a task without providing examples first.

Chain-of-thought reasoning asks the model to think step by step before producing a final answer. This often improves reasoning accuracy.

Structured reasoning workflows help the model follow a sequence of steps while solving problems. This improves reliability and reduces mistakes.

Hallucination happens when an AI model invents information that is not supported by the source material.

Grounding means ensuring that all generated information can be traced back to the provided notes or data source.

Edge case handling means planning for situations where the input is empty, unclear, or too short to complete the task properly.

Acronyms should be expanded in prompts when clarity is important. For example, Application Programming Interface (API) should not appear only as API.

System prompts are usually static instructions that define the behaviour of the AI model throughout the conversation.

User prompts are dynamic instructions that change depending on the user's request and input data.

Separating prompts from code makes it easier to update instructions without changing the application logic.

Large Language Models (LLMs) often perform better when instructions are repeated at both the beginning and end of a prompt.

Verification steps can help reduce hallucinations by asking the model to confirm that information exists in the source notes before generating an answer.

Direct quotes from source notes provide evidence that the generated answer is grounded in the original material.

Real-world prompt engineering often requires iteration, testing, and refinement before reliable results are achieved.
